## 问题 1：黄巾到黄金 强制替换污染玩家记忆

### 现象
> 玩家心里嘀咕：史书上明明写的是黄金，眼前这旗咋成了黄金？

玩家记忆设定是 史书上是黄巾 世界是黄金（世界观核心：玩家记得真相，世界被改写）。但输出里玩家自己说 史书上是黄金——玩家记忆被污染，核心悬念崩坏。

### 根因（代码级）
- backend/engine/writer.py:732
-  data[narrative] = data[narrative].replace(黄巾, 黄金)
这行本意是 世界侧统一称呼——但它是无差别全局替换，把玩家内心回忆里的 黄巾 也替换成了 黄金。LLM 原本正确写出了 史书上写的是黄巾，眼前却成了黄金 这个核心差异，被替换后变成 史书上写的是黄金，眼前也是黄金——玩家记忆与世界的对比消失了。

### 影响
- 世界观核心悬念（玩家是唯一记得真相的人）被破坏
- 黄金 vs 黄巾 的认知差异是玩家视角的关键钩子，被抹平后 player_pov 失去意义

### 修复建议
1. P0：删除这行全局替换，改为只替换世界侧叙述（NPC 台词/旁白），不碰玩家内心/回忆
2. P1：如果担心 LLM 串味，改为只在 非玩家内心 的段落替换（用 你心想/你嘀咕/你记得 等前缀判定）

## 问题 2：标题 P2 洛阳暗夜 189年 vs 正文颍川 184——日期与位置脱节

### 现象
> 标题 P2 洛阳暗夜 189年8月1日，但正文开头 你落脚在颍川官道边……黄金军打过来了——标题在洛阳 189 年，正文在颍川 184 年内容。

### 根因（代码级）
- 跳转（静观其变）只推进 world_date（184-02 到 189-08），不改 player.location（仍为颍川）
- backend/engine/world.py:306-308：loc = match_location(action) or cur_loc——跳转动作不是地点动作，loc 保持颍川，era.location = 颍川
- backend/engine/director.py view_scene：场景内容（设定/atmo/在场）只按 player.location 选，不按日期选——189 年的颍川仍按 P1 黄金乱起演
- backend/engine/graph.py:47-48：era.chapter 由 view_scene(plan.chapter) 派生——日期已 189 但 chapter 仍 P1
- 前端 PlayPage.vue:688 eraChapter 显示 era.chapter；但正文由 view_scene 合成，标题与正文脱节

### 影响
- 玩家看到 时代已到 189 洛阳 却仍在颍川打黄金军——时间线错乱感
- 名场面（董卓进京 189-08）永远无法触发（因为 location 不在洛阳）

### 修复建议
1. P0：跳转（force skip）时把 player.location 同步到跳转目标事件的主地点（如 189-08 董卓进京 到 洛阳）
2. P0：view_scene 场景选择加入日期维度——189 年的颍川应演 P2 的颍川常态而非 P1 黄金乱起
3. P1：scene 事件与 state 事件用同一份 plan（消除 pre_state 滞后）

## 问题 3：事件跳转 3 次没反应

### 现象
> 玩家点 跳到下一事件 3 次，没有任何反应（没有跳转的描写，事件也没有跳转，还是接着写）

### 根因（代码级 + 实测）
- 后端跳转逻辑本身是好的（实测：advance_world 静观其变 到 date 184-02 到 184-04、事件进队列、new_briefing=True）
- 但叙事层没体现跳转：
-  - writer 的 continuity 块只说 从上一拍结尾继续推进，没有 本拍发生了时间跳跃 X 个月 的强制指令
-  - LLM 收到玩家行动 静观其变，理解为 原地等待，写出的还是原地叙事
-  - 跳转后 due_events 的事件进 world_events 队列，但不强制进叙事正文（只可能弹简报）
- 另外：next_timeline_skip 只找下一条时间线事件（184-04），单次跳转只推进 2 个月——玩家点 3 次也只到 184-10 左右，远不到 189，观感上 跳了个寂寞

### 修复建议
1. P0：跳转时把 时间跳跃 X 个月 + 期间大事 强制写进叙事指令
2. P0：跳转后 new_briefing 的简报要强弹（不只进列表），让玩家感知 世界前进了
3. P1：快速跳转改为直接跳到下一个 强相关/名场面 事件（而非下一条任意事件），让跳转有实质内容

## 问题 4：文风严肃别扭

### 现象
> 文风太过严肃、别扭——部分段落吐槽生硬，对话口语化不足，幽默感不稳定。

### 根因（代码级）
- 文风规则（writer.py 第 3 条）已含吐槽密度/防重复，但规则是描述性的，LLM 执行不稳定
- 玩家行动注入（最后一条 user）与 instruction（4-6KB）分离，LLM 注意力被 instruction 的场景设定吸引，文风规则被稀释
- 这世道/品牌包装 等已做输出层替换，但替换治标不治本——LLM 仍倾向用固定句式

### 修复建议
1. P1：文风规则前移（放进 system prompt 而非 user instruction 尾部），让 LLM 更早建立风格基线
2. P1：加 2-3 条风格正例 few-shot（一句示例 + 要求变换说法）
3. P2：输出后处理加 书面语到口语 微调（并非 到 不是、甚为 到 挺 等高频书面词映射）

## 问题 5：在场判断混乱

### 现象
> 叙事里反复出现的 黑脸汉子/黄袍老头/逃兵 等角色，在场面板时有时无；已离场的角色有时还挂着。

### 根因（代码级）
- 在场名单 = present（distance_map + character_updates 角色名）
- LLM 不一定会把叙事里登场的人物写进 character_updates——黑脸汉子/黄袍老头是叙事即兴角色，LLM 只写 narrative 没声明 character_updates，不在 present
- backend/engine/character_states.py:186-189：陌生即兴 NPC 被过滤（不登记）——黑脸汉子 这种没名字的即兴角色永远不会进 character_states，面板缺失
- 已离场角色残留：present 每拍重算（distance_map 按地点过滤）——同场景内离场的角色 present 不含他，面板正确；跨场景靠 update_char_facts 置 行踪未明，基本正确，但即兴 NPC 无地点关联清不掉

### 修复建议
1. P1：present 名单改为 distance_map + character_updates + 叙事 events 里的 actor——LLM 即使没写 character_updates，events 里的 actor 也能进在场
2. P1：对有名字的即兴角色（黄袍老头/黑脸汉子）放宽登记——保留无名字群像（难民/兵丁）过滤
3. P2：在场面板区分 在场 和 相识过（后者可折叠显示）

## 问题 6：重复叙事（逃兵 仙人救命 x3、同场景反复重演）

### 现象
> 1. 逃兵跪地喊 仙人救命 至少出现 3 次（每次措辞略不同）
> 2. 老汉把饼收回去 木牌哗啦啦响 等画面反复出现
> 3. 同场景内容被反复重演

### 根因（代码级）
- backend/engine/writer.py:609：历史只喂最近 6 条（约3轮）——3 轮前的 逃兵登场 被挤出上下文窗口
- performed_events 去重键是 memory_add 文本——LLM 每次生成的摘要措辞不同，去重键失效，防不住重演
- 场景内 beat_index 递增但 LLM 无长期记忆（LTM 是扁平的，不保证回读）

### 修复建议
1. P0：历史窗口 6 条 到 12 条（约6轮，与 history 保留 12 轮对齐）——逃兵 3 轮内的登场就不会被挤出
2. P0：performed_events 去重升级——按事件关键词（如 逃兵/仙人 出现过的就标记已演）而非全文
3. P1：连续性块加 本场景已出场人物清单（present 名单 + 关键 NPC 名）——LLM 明确知道谁已经登场过，禁止重新介绍

## 结论

核心病灶是 世界时钟 与 玩家位置 脱节（问题2/3 的根源）——跳转/时间推进只改日期不改位置，导致标题、正文、事件、在场全部错位。其次是 上下文窗口太小（问题6）导致的失忆重演，以及 无差别文本替换（问题1）污染玩家记忆。这三个是 P0 级硬伤，修好后叙述逻辑的整体一致性会有质变。
