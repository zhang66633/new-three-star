## 一、引擎架构总览（LangGraph 图）

```
                    ┌─────────────────────────────────────────────┐
                    │               LangGraph 图                   │
 玩家输入 ──► START ──► director ──► narrate ──► validate ──► remember ──► END
                    │   (选场景)    (生成叙事)  (8PHASE门禁)  (记忆晋升)    │
                    │      ▲          │ 失败(≤2次重写)  │                │
                    │      │          ▼                ▼                │
                    │  state: 骨架导航  修正机制      状态更新           │
                    └─────────────────────────────────────────────┘
                                    │
                    API 层 (FastAPI routers/narrative.py)
                                    │
                    前端 (Vue3 电影史诗感叙事界面)
```

**节点职责**：
| 节点 | 职责 | 纯逻辑/LLM |
|------|------|-----------|
| `director` | 读 State → 选下一场景（骨架导航 + 状态驱动岔路）| 纯代码 |
| `narrate` | 生成叙事文本 + 选项 | LLM（Writer）|
| `validate` | 8 PHASE 硬校验，不过则触发重写（≤2 次）| LLM（Validator）|
| `remember` | STM 满 6 条 → LLM 压缩 → 晋升 LTM + 索引重建 | LLM + rag 索引 |
| `修正节点` | 玩家干预度超阈值 → 按档位执行天意修正 | LLM（修正 Writer）|

## 二、State Schema（LangGraph State）

```python
class GameState(TypedDict):
    # ── 玩家 ──
    player: PlayerState          # 身份/声望/生存状态/位置/穿越记忆碎片
    # ── 时代 ──
    era: EraState                # 当前篇章/年份/大势/已发生事件
    # ── 世界 ──
    relations: dict[str, int]    # 10+ NPC 好感值 0-100
    trust: dict[str, int]        # 信任值（与好感分离：好感=态度，信任=信不信你的话）
    flags: list[str]             # 状态标记（暗线/见证者/知情者等）
    # ── 知识分层（信息迷雾）──
    knowledge: KnowledgeState    # public(玩家已见) / hidden(世界真实) / player(穿越直觉)
    # ── 记忆（向量检索）──
    memory: MemoryState          # STM[≤6] / LTM[] / PIN[]（rag 索引托管）
    # ── 剧情 ──
    skeleton_pos: str            # 当前骨架位置（篇章/场景 id）
    tension: int                 # 历史干预度累计（0-100）
    corrected: list[str]         # 已发生的修正记录（玩家知情 flag 来源）
    # ── 引擎 ──
    turn: int                    # 轮次
    last_output: NarrativeOutput # 上轮输出（供 validate 对比）
```

## 三、8 PHASE 校验（validate 节点）

> 映射自 AAA 规范；硬校验项目，未过则触发重写（最多 2 次，重写时注入失败原因）。

| PHASE | 检查项 | 判定 | 硬校验/自检 |
|-------|--------|------|------------|
| P0 时空锚定 | 时间/季节/天气/位置与上轮连续；大跳跃显式标记 | 连续或已标记 ✓ | 硬校验 |
| P1 真实性 | 地理/人物/事件符合三国史实或骨架设定 | 无硬伤 ✓ | 硬校验 |
| P2 意图与记忆 | 玩家上轮选择被回应；未解伏笔/承诺被追踪 | 无遗漏 ✓ | 硬校验 |
| P3 人物一致 | 登场 NPC 性格/OOC/语言风格/关系值一致 | 无 OOC ✓ | 硬校验 |
| P4 防崩坏 | 防神化/渐进性/真实性 | 通过 ✓ | 硬校验 |
| P5 行为后果 | 本次选择的法律/经济/关系/声望后果已结算；无预设交流 | 已结算 ✓ | 硬校验 |
| P6 场景氛围 | 光/声/味/温/人流覆盖 | 覆盖 ✓ | prompt 自检 |
| P7 输出质量 | 描写均衡/感官细节/情感链/篇幅 | 达标 ✓ | prompt 自检 |

**信息迷雾专项**（validate 内置）：
- 输出文本中不得出现 `knowledge.hidden` 区信息（NPC 说了他不知道的事/旁白泄漏远处事件）
- NPC 发言只能基于其注入的记忆（按关系/立场过滤后的人设）
- 玩家"穿越直觉"被合理演出（当作疯话/被忽略，NPC 不当真）

## 四、记忆系统（向量检索）

### 4.1 三层结构
| 层 | 容量 | 内容 | 管理 |
|----|------|------|------|
| STM 短期 | ≤6 条 × 50-80 字 | 当前场景客观事实 | 每轮更新，满 6 晋升 |
| LTM 长期 | 无上限 × 120-150 字 | 跨场景持久事实 | remember 节点压缩生成 |
| PIN 钉选 | ≤5 条 | 玩家手动标记的重要记忆 | UI 长按钉选，永不压缩，检索优先 |

### 4.2 检索流程（每轮 narrate 前）
1. 查询 = 当前场景描述 + 玩家上轮输入
2. `rag.search()`（复用：TF-IDF + DeepSeek Embedding + RRF 融合）
3. 注入 = **PIN 全部 + 检索 top-5 LTM + 当前 STM**
4. 排序：PIN 最前，按重要度+时效

### 4.3 索引维护
- STM 满 6 条 → `remember` 节点：LLM 压缩合并 → 写入 LTM → **全量重建索引**（记忆量小，成本可接受；TF-IDF 统计一致性要求全量）

## 五、天意修正机制

### 5.1 干预度（historical_tension）
每个重大选项显式标注 0-100：
| 档位 | 值域 | 含义 | 修正级别 |
|------|------|------|---------|
| 顺历史 | 0-30 | 顺应史实/无关 | 不触发 |
| 局部干预 | 31-70 | 改过程不改结果 | 轻修正（细节改写） |
| 硬干预 | 71-100 | 想改变历史结局 | 重修正（事件重生成/时间跳跃） |

### 5.2 修正执行（修正节点，按档位选 5 种痕迹之一）
1. 时间跳跃（下一场景自然衔接"几个月后"）
2. 记忆覆盖（NPC 按"新记忆"行事，无人察觉矛盾）
3. 事件重生成（历史结果以正常叙述达成，如粮仓"自己烧了"）
4. 对话自然转向（关键话题被正常话题接走）
5. 巧合堆叠（信使迷路/文书浸水/守卫换班）

### 5.3 呈现原则
- 世界侧一切正常，零提示零讨论
- 玩家是唯一察觉差异的人（记录 `corrected` flag + "知情者"状态）
- 修正不是惩罚：关系/声望照常结算，修正=荒诞喜剧原料

## 六、信息迷雾（知识分区）

```
KnowledgeState:
├─ public: 玩家已见内容（看到/听到/对话）→ 可注入 Writer 输出
├─ hidden: 世界真实（NPC内心/远处事件/未来走向）→ validate 禁止泄漏
└─ player: 穿越记忆/历史直觉 → 仅玩家可引用（NPC 不当真）
```

  ],
  "state_updates": {
    "relations": {"曹操": +5},
    "flags": ["见证者_官道之辩"],
    "memory_add": ["STM 新增条目"]
  }
}

## 八、角色人设分层注入（靠近才加载）

| 距离 | 注入内容 |
|------|---------|
| 远观（场景提及） | 名字 + 身份 + 一句性格 |
| 互动（对话/同行） | 完整人设卡：性格/目标/关系值/信任值/记忆/台词风格 |
| 核心（当前场景主要角色） | 完整人设 + 专属机制（素材库 A5）+ 该场景的梗台词引用 |

## 九、文件结构（目标）

```
backend/
├── engine/
│   ├── graph.py          # LangGraph 图定义（State/Nodes/Edges）
│   ├── state.py          # GameState Schema
│   ├── director.py       # 场景导航（骨架 + 状态驱动岔路 + tension 判定）

│   ├── validator.py      # 8 PHASE 校验 + 信息迷雾检查
│   ├── remember.py       # 记忆晋升 + 索引重建
│   ├── corrector.py      # 天意修正执行
│   └── prompts/          # 世界底色/修正指令/人设卡/PHASE 检查清单
├── routers/narrative.py  # API 层（调用编译后的图）
└── services/
    ├── llm.py            # DeepSeek 调用（保留）
    ├── rag.py            # 复用（记忆检索）
    └── deslop.py         # 去AI味（保留为 writer 后处理）
```
