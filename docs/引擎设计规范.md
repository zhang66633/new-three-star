## 一、引擎架构总览（LangGraph 图）

```
                    ┌─────────────────────────────────────────────┐
                    │               LangGraph 图                   │
 玩家输入 ──► START ──► director ──► narrate ──► validate ──► remember ──► END
                    │   (选场景)    (生成叙事)  (8PHASE门禁)  (记忆晋升)    │
                    │      ▲          │ 失败(≤2次重写)  │                │
                    │      │          ▼                ▼                │
                    │  state: 骨架导航  修正机制      状态更新           │
                    └─────────────────────────────────────────────┘
                                    │
                    API 层 (FastAPI routers/narrative.py)
                                    │
                    前端 (Vue3 电影史诗感叙事界面)
```

**节点职责**：
| 节点 | 职责 | 纯逻辑/LLM |
|------|------|-----------|
| `director` | 读 State → 选下一场景（骨架导航 + 状态驱动岔路 + 世界时钟推进 / 名场面就位判定）| 纯代码 |
| `narrate` | 生成叙事文本 + 选项 | LLM（Writer）|
| `validate` | 8 PHASE 硬校验，不过则触发重写（≤2 次）| LLM（Validator）|
| `remember` | STM 满 6 条 → LLM 压缩 → 晋升 LTM + 索引重建 | LLM + rag 索引 |
| `修正节点` | 玩家干预度超阈值 → 按档位执行天意修正 | LLM（修正 Writer）|

## 二、State Schema（LangGraph State）

```python
class GameState(TypedDict):
    # ── 玩家 ──
    player: PlayerState          # 身份/声望/生存状态/位置/穿越记忆碎片
    # ── 时代 ──
    era: EraState                # 当前篇章/年份/大势/已发生事件
    # ── 目标（世界时钟）──
    world_clock: dict            # 名场面时间轴 {chapter, current_season, turns_left}——准备期行动消耗世界时间、时钟推进（见 §六）
    # ── 世界 ──
    relations: dict[str, int]    # 10+ NPC 好感值 0-100
    trust: dict[str, int]        # 信任值（与好感分离：好感=态度，信任=信不信你的话）
    flags: list[str]             # 状态标记（暗线/见证者/知情者等）
    # ── 知识分层（信息迷雾）──
    knowledge: KnowledgeState    # public(玩家已见) / hidden(世界真实) / player(穿越直觉)
    # ── 记忆（向量检索）──
    memory: MemoryState          # STM[≤6] / LTM[] / PIN[]（rag 索引托管）
    # ── 剧情 ──
    skeleton_pos: str            # 当前骨架位置（篇章/场景 id）
    tension: int                 # 历史干预度累计（0-100）
    corrected: list[str]         # 已发生的修正记录（玩家知情 flag 来源）
    # ── 引擎 ──
    turn: int                    # 轮次
    scene_state: dict            # 连续性子系统：上一拍连续性事实 + qualifications（已积累就位条件，名场面门禁，见 §六）
    last_output: NarrativeOutput # 上轮输出（供 validate 对比）
```

## 三、8 PHASE 校验（validate 节点）

> 映射自 AAA 规范；硬校验项目，未过则触发重写（最多 2 次，重写时注入失败原因）。

| PHASE | 检查项 | 判定 | 硬校验/自检 |
|-------|--------|------|------------|
| P0 时空锚定 | 时间/季节/天气/位置与上轮连续；大跳跃显式标记 | 连续或已标记 ✓ | 硬校验 |
| P1 真实性 | 地理/人物/事件符合三国史实或骨架设定 | 无硬伤 ✓ | 硬校验 |
| P2 意图与记忆 | 玩家上轮选择被回应；未解伏笔/承诺被追踪 | 无遗漏 ✓ | 硬校验 |
| P3 人物一致 | 登场 NPC 性格/OOC/语言风格/关系值一致 | 无 OOC ✓ | 硬校验 |
| P4 防崩坏 | 防神化/渐进性/真实性 | 通过 ✓ | 硬校验 |
| P5 行为后果 | 本次选择的法律/经济/关系/声望后果已结算；无预设交流 | 已结算 ✓ | 硬校验 |
| P6 场景氛围 | 光/声/味/温/人流覆盖 | 覆盖 ✓ | prompt 自检 |
| P7 输出质量 | 描写均衡/感官细节/情感链/篇幅 | 达标 ✓ | prompt 自检 |

**信息迷雾专项**（validate 内置）：
- 输出文本中不得出现 `knowledge.hidden` 区信息（NPC 说了他不知道的事/旁白泄漏远处事件）
- NPC 发言只能基于其注入的记忆（按关系/立场过滤后的人设）
- 玩家"穿越直觉"被合理演出（当作疯话/被忽略，NPC 不当真）

## 四、记忆系统（向量检索）

### 4.1 三层结构
| 层 | 容量 | 内容 | 管理 |
|----|------|------|------|
| STM 短期 | ≤6 条 × 50-80 字 | 当前场景客观事实 | 每轮更新，满 6 晋升 |
| LTM 长期 | 无上限 × 120-150 字 | 跨场景持久事实 | remember 节点压缩生成 |
| PIN 钉选 | ≤5 条 | 玩家手动标记的重要记忆 | UI 长按钉选，永不压缩，检索优先 |

### 4.2 检索流程（每轮 narrate 前）
1. 查询 = 当前场景描述 + 玩家上轮输入
2. `rag.search()`（复用：TF-IDF + DeepSeek Embedding + RRF 融合）
3. 注入 = **PIN 全部 + 检索 top-5 LTM + 当前 STM**
4. 排序：PIN 最前，按重要度+时效

### 4.3 索引维护
- STM 满 6 条 → `remember` 节点：LLM 压缩合并 → 写入 LTM → **全量重建索引**（记忆量小，成本可接受；TF-IDF 统计一致性要求全量）

## 五、天意修正机制

### 5.1 干预度（historical_tension）
每个重大选项显式标注 0-100：
| 档位 | 值域 | 含义 | 修正级别 |
|------|------|------|---------|
| 顺历史 | 0-30 | 顺应史实/无关 | 不触发 |
| 局部干预 | 31-70 | 改过程不改结果 | 轻修正（细节改写） |
| 硬干预 | 71-100 | 想改变历史结局 | 重修正（事件重生成/时间跳跃） |

### 5.2 修正执行（修正节点，按档位选 5 种痕迹之一）
1. 时间跳跃（下一场景自然衔接"几个月后"）
2. 记忆覆盖（NPC 按"新记忆"行事，无人察觉矛盾）
3. 事件重生成（历史结果以正常叙述达成，如粮仓"自己烧了"）
4. 对话自然转向（关键话题被正常话题接走）
5. 巧合堆叠（信使迷路/文书浸水/守卫换班）

### 5.3 呈现原则
- 世界侧一切正常，零提示零讨论
- 玩家是唯一察觉差异的人（记录 `corrected` flag + "知情者"状态）
- 修正不是惩罚：关系/声望照常结算，修正=荒诞喜剧原料

## 六、世界时钟与名场面目标

> 方案定稿（2026-08-08，用户逐问确认 6 项决策）：主线骨架 + 名场面时间窗——保留现有场景骨架作为名场面链（非开放世界）。玩家在名场面之间的准备期自由行动、世界时钟推进、名场面时节就位判定：错过关键名场面即失败，仅关键节点自动存档。

### 6.1 核心循环与目标可见

```
章首揭示（本章时间轴 + 名场面链）→ 准备期行动盘自由行动（消耗时间 + 积累就位条件）
→ 世界时钟推进 → 名场面时节到：就位判定
     ├─ 就位条件满足 → 触发名场面（进入现有场景叙事）
     └─ 不满足 → 错过关键名场面 → 游戏失败 → 读档回上个名场面重打
```

| 环节 | 说明 | 落点 |
|------|------|------|
| 章首揭示 | 全可见：本章时间轴 + 名场面链（时节 / 就位条件 / 剩余时间），玩家明确要赶什么 | 前端章首面板 + `world_clock` |
| 准备期行动盘 | 名场面之间从 `prep_actions` 选准备行动（投靠 / 乔装 / 买情报 / 赶路） | registry 场景 `prep_actions` |
| 世界时钟推进 | 准备行动消耗世界时间，时钟按季节推进 | director（纯代码）|
| 名场面时节到 | 就位条件满足 → 触发名场面；不满足 → 错过关键名场面 → 失败 | `fame_moment` / `entry_conditions` 判定 |

### 6.2 世界时钟推进（时间轴）

- `world_clock` 为 state 顶层键：`{chapter, current_season, turns_left}`；每章一条时间轴（如 189 年春夏秋冬），名场面锚定时节（`fame_season`）。
- 推进在 `director`（纯代码，零 LLM）：场景导航时读 `world_clock`，准备期行动按 `cost_turns` 扣减 `turns_left`；扣尽则 `current_season` 前进、`turns_left` 重置。
- 名场面时节到即按 §6.3 就位判定。若后续需要"时节事件插播 / 时间跳跃演出"，可拆独立纯代码时间节点，但当前不新增 LLM 节点（避免放大成本）。

### 6.3 就位判定（名场面门禁）

- 关键名场面场景声明 `entry_conditions`（就位条件列表，如 `["在曹操身边"]`）；玩家已积累就位条件存 `scene_state.qualifications`。
- 判定：名场面时节到时，`entry_conditions ⊆ qualifications` → 就位，触发名场面；否则未就位 → 错过。
- 失败粒度：仅 `fame_moment=true` 的关键名场面错过才失败；普通场景错过不失败、自然推进。

### 6.4 超时失败与读档

- 关键名场面开始前自动存档（服务端持久化，见 §6.7）；失败读档回上个名场面存档点重打（覆盖式，保留最近一档）。
- 普通场景不设存档点（错过不失败）。

### 6.5 准备期行动盘（接入 narrate/options 循环）

- 名场面之间的准备期，前端以行动盘呈现当前可用 `prep_actions`；玩家点选 = 一个普通 action，走现有 `director → narrate → validate → remember` 循环：
  1. director（纯代码）：按所选行动 `cost_turns` 扣减 `world_clock.turns_left`，扣尽推进时节
  2. narrate：为准备行动生成叙事（照常过 8 PHASE 校验）
  3. 状态更新：行动 `grants` 累积进 `scene_state.qualifications`
  4. 名场面时节到 → 按 §6.3 就位判定，就位则切入名场面场景叙事
- `prep_actions` 单条结构：`{text, cost_turns, grants[就位条件], effect}`。

### 6.6 场景注册表（registry）名场面字段

在现有场景字段（scene_id / chapter / year / season / … / flags_on_enter / aftermath / min_turns）基础上新增：

| 字段 | 类型 | 含义 | 示例 |
|------|------|------|------|
| `fame_moment` | bool | 是否关键名场面（错过即失败） | `true` |
| `fame_season` | str | 名场面锚定时节（对齐 `world_clock.current_season`） | `"夏"` |
| `entry_conditions` | list[str] | 触发名场面所需的就位条件列表 | `["在曹操身边", "身份未暴露"]` |
| `prep_actions` | list[dict] | 名场面前的准备期行动盘 | `{"text": "赶路投靠曹操", "cost_turns": 2, "grants": ["在曹操身边"], "effect": "消耗 2 回合，到达陈留"}` |

> 注：这些字段对现有场景可选——缺省 `fame_moment=false` 时行为与现状一致（普通场景链不变）；仅关键名场面补齐即可。

### 6.7 存档机制（服务端持久化）

- 存档落库 `backend/worlds.db`（复用现有 db.py 的 aiosqlite 连接，新增存档表），GameState 经 `to_dict` 序列化为 JSON 存入。
- 自动存档点：关键名场面（`fame_moment=true`）开始前。
- 读档：失败读档回上个名场面存档点重打（覆盖式保留最近一档）。

## 七、信息迷雾（知识分区）

```
KnowledgeState:
├─ public: 玩家已见内容（看到/听到/对话）→ 可注入 Writer 输出
├─ hidden: 世界真实（NPC内心/远处事件/未来走向）→ validate 禁止泄漏
└─ player: 穿越记忆/历史直觉 → 仅玩家可引用（NPC 不当真）
```

## 八、输出 Schema（narrate 节点生成）

```json
{
  "narrative": "叙事正文（目标 600-1000字，硬下限 150 字，含玩家视角差异呈现）",
  "options": [
    {
      "text": "选项描述",
      "type": "major|minor",
      "tension": 45,
      "effect": "关系/声望/flag 变更说明（对玩家可见）"
    }
  ],
  "state_updates": {
    "relations_delta": {"曹操": +5},
    "flags_add": ["见证者_官道之辩"],
    "memory_add": ["STM 新增条目"]
  }
}
```

> 注：state_updates 实际字段为 `relations_delta`/`trust_delta`/`flags_add`/`memory_add`/`foreshadowing_add`/`rumors_add`（writer._extract_state_updates 产出，graph.remember_node 消费）。叙事目标字数与互动叙事引擎规范 P7 的"≥1000"存在出入，当前以 600-1000 为准。

## 九、角色人设分层注入（靠近才加载）

| 距离 | 注入内容 |
|------|---------|
| 远观（场景提及） | 名字 + 身份 + 一句性格 |
| 互动（对话/同行） | 完整人设卡：性格/目标/关系值/信任值/记忆/台词风格 |
| 核心（当前场景主要角色） | 完整人设 + 专属机制（素材库 A5）+ 该场景的梗台词引用 |

## 十、文件结构（当前实际）

```
backend/
├── engine/
│   ├── graph.py          # LangGraph 图定义（State/Nodes/Edges）+ 流式回调(ContextVar)
│   ├── state.py          # GameState Schema + from_dict 白名单/长度钳制（world_clock / scene_state.qualifications）
│   ├── director.py       # 场景导航（骨架 + 状态驱动岔路 + tension 判定 + era 写回 + 世界时钟推进 / 名场面就位判定）
│   ├── writer.py         # 叙事生成（状态面板/知识边界/选项池注入 + 后处理）
│   ├── validator.py      # 8 PHASE 校验（确定性硬/软拆分 + LLM 层 + 信息迷雾）
│   ├── remember.py       # STM/LTM/PIN + 检索（关键词+时效打分）
│   ├── corrector.py      # 天意修正执行
│   └── scenes/registry.json  # 场景注册表（名场面字段：fame_moment / fame_season / entry_conditions / prep_actions）
├── routers/play.py       # API 层（SSE 流式，post-validate 发送最终叙事）
├── routers/{archive,worlds,worldview,graph}.py  # 世界观档案/创作（旧 PRD 功能）
├── db.py                 # worlds.db 持久化（aiosqlite：世界观档案 + GameState 名场面存档）
└── services/
    ├── llm.py            # DeepSeek/Hy3 调用（流式）
    ├── rag.py            # 知识库素材检索（当前未接入 LTM 记忆，保留）
    ├── deslop.py         # 去AI味（writer 后处理）
    ├── validator.py      # 确定性修复（道具名/选项/名混用）
    ├── framework_picker.py / prompt_builder.py  # 旧 PRD 世界观生成
    └── ...
```

> 注：早期 spec 规划的 `routers/narrative.py` 与 `engine/prompts/` 目录已改为：叙事接口在 `routers/play.py`，提示词内联在各 engine 模块（WORLD_BASE/CORRECTOR_PROMPT 等）。旧引擎 `services/{director,persona,recorder,writer}.py` 已删除。
